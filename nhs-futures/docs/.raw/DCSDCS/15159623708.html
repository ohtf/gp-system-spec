Description

Supports the delivery of communications to recipients.

Outcomes

For a Health or Care Organisation:

Ability to manage communications via a central service, reducing administrative burden and costs, as well as informing recipients.

MUST Epics - Describes the minimum functionality required to deliver a Capability. Solutions MUST be successfully evaluated against each Epic and Acceptance Criteria via Capability Assessment in order to be associated with this Capability

E00367 - create communications

As a Health or Care Professional

I want to create communications

So that I can communicate with recipients

Acceptance criterion 1: create a communication

Given the Health or Care Professional is permitted to create communications

When the Health or Care Professional selects to create a communication

Then the communication is created

E00367 - Supporting Information

  • Communications MAY be sent to Patient/Service Users or Health or Care Professionals

  • A communication MAY be sent via, but is not limited to:

    • Email

    • SMS

    • Letter

    • Direct Message

MAY Epics - Describes additional functionality associated with the Capability. Suppliers should consider all MAY Epics as part of their User Research. Suppliers can choose to map their Solutions to these Epics and they will be evaluated via Capability Assessment. Contracting Authorities or purchasing organisations may require these Epics as product qualification or requirements criteria

E00368 - manage communications to Patients/Service Users

As a Health or Care Professional

I want to manage communications to Patients/Service Users

So that I can communicate with Patients/Service Users

Acceptance criterion 1: record consent for a specific communication channel

Given the Health or Care Professional is permitted to manage communications to Patients/Service Users

When the Health or Care Professional selects to record that the Patient/Service User has consented to receive communication via a particular channel

Then the consent is recorded

Acceptance criterion 2: record dissent for a specific communication channel

Given the Health or Care Professional is permitted to manage communications to Patients/Service Users

When the Health or Care Professional selects to record that the Patient/Service User has dissented to receive communication via a particular channel

Then the dissent is recorded

Acceptance criterion 3: view consent record for a specific communication channel

Given the Patient/Service User has an existing consent record for a specific communication channel

When the Health or Care Professional selects to view the consent record

Then the Patient/Service User’s consent record is displayed

Acceptance criterion 4: create a communication to a Patient/Service User

Given the Health or Care Professional is permitted to manage communications to Patients/Service Users

When the Health or Care Professional selects to create a communication to a Patient/Service User

Then the communication is created

Acceptance criterion 5: record a communication to a Patient/Service User’s record

Given the Health or Care Professional has created a communication to a Patient/Service User

When the communication to a Patient/Service User is created

Then the communication is recorded to the Patient/Service User’s record

E00368 - Supporting Information

  • The details of the communication recorded on the Patient/Service User’s record MAY include, but is not limited to:

    • Creator name

    • Creation date and time

    • Recipient(s)

    • Status (e.g. sent, failed)

    • Status date & time

  • A communication MAY be sent via, but is not limited to:

    • Email

    • SMS

    • Letter

    • Direct Message

E00379 - manage incoming communications

As a Health or Care Professional

I want to manage incoming communications

So that incoming communications can be managed

Acceptance criterion 1: manage incoming communications

Given incoming communications are permitted by the Health or Care Organisation

When an incoming communication is received

Then the communication is managed

E00379- Supporting Information

  • Incoming communications MAY include, but are not limited to:

    • receiving an SMS message from a Patient/Service User to cancel an Appointment

    • receiving an email from a Patient/Service user to enquire about test results

  • The management of incoming communications MAY include, but is not limited to:

    • Receiving incoming communications

    • Organising received communications

    • Associating created communications with received communications

    • Triggering further actions within the Solution (e.g. cancelling an Appointment)
