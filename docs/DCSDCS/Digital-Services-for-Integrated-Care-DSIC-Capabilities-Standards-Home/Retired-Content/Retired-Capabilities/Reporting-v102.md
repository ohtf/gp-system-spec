# Reporting v1.0.2

|  |  |
| --- | --- |
| ID | C16 |
| Version | 1.0.2 |
| Type | Capability |
| Category | Reporting and data analytics |
| Status | Retired |
| Effective Date | 23 Nov 2022 |

# Description

Enables reporting and analysis using a range of data items to support clinical care and Health or Care Organisation management.

# Outcomes

|  |  |
| --- | --- |
| For Health or Care Organisations: | Have the tools to be able to analyse data locally, which will support areas such as clinical care, finance, audit and operational needs. |

| **MUST Epics - Describes the minimum functionality required to deliver a Capability. Solutions MUST be successfully evaluated against each Epic and Acceptance Criteria via Capability Assessment in order to be associated with this Capability** |
| --- |
| E00344 - report on a range of data items As a Health or Care Professional  I want reports to use a range of data items  So that I can run reports based on a range of data items Acceptance criterion 1: define report criteria Given the Health or Care Professional is permitted to create reports  When the Health or Care Professional selects to define the criteria for a report  Then the Health or Care Professional can select a range of data items Acceptance criterion 2: view report results Given the Health or Care Professional is permitted to view report results  When the Health or Care Professional selects to view the report  Then the report results are displayed E00344 - Additional Implementation Details Solutions MUST comply with the following when implementing this Epic:   - Ability to report on a range of data items provided by achieving compliance with multiple different Capabilities (Data items can be provided by one or more Solutions) - Reporting functions to be available between the hours of 8am to 6pm daily, as a minimum E00344 - Supporting Information  - Report criteria MAY include, but are not limited to:    - Any combination of coded or structured data held within or linked to the Patient/Service User Record   - Historic and future dates or date ranges   - Defined time periods (e.g. in the last 6 months)   - Inclusion or exclusion of deceased or inactive Patients/Service Users   - Data items which are no longer active or are prevented from ongoing use in Patient/Service User Records - It is recommended that reporting functions are available at all times when the Solution is available for use - It is recommended that data used in reporting is fully up to date to enable decisions to be made without compromising Patient/Service User care - For coded data, see Data Standards for requirements |

| **MAY Epics - Describes additional functionality associated with the Capability. Suppliers should consider all MAY Epics as part of their User Research. Suppliers can choose to map their Solutions to these Epics and they will be evaluated via Capability Assessment. Framework Authorities or purchasing organisations may require these Epics as product qualification or requirements criteria** |

| E00345 - include Synthetic Patients/Service Users in reports As a Health or Care Professional  I want to configure reports to include Synthetic Patients/Service Users  So that I can test reports before they are used operationally Acceptance criterion 1: include Synthetic Patients/Service Users in reports Given the Health or Care Professional is permitted to create reports  When the Health or Care Professional selects to include Synthetic Patients/Service Users in the report results  Then Synthetic Patients/Service Users are included in the report results  And any Synthetic Patients/Service Users are indicated in the report results Acceptance criterion 2: exclude Synthetic Patients/Service Users from reports Given the Health or Care Professional is permitted to create reports  When the Health or Care Professional selects to exclude Synthetic Patients/Service Users from the report results  Then Synthetic Patients/Service Users are excluded from the report results E00345 - Supporting Information  - Synthetic Patients/Service Users are records which can be used by some live processes but which do not relate to any existing person. For further information about Synthetic Data see the Master Glossary  ---  E00346 - configure display of report results As a Health or Care Professional  I want to configure how the results of reports are displayed  So that I can view the report results in the most appropriate way Acceptance criterion 1: configure display of report results Given a Health or Care Professional is permitted to view report results  When the Health or Care Professional selects to configure the display of the report results  Then the report results are displayed as configured E00346 - Supporting Information  - Configuration MAY include, but is not limited to:    - Viewing a list of Patients/Service Users who meet defined criteria   - Displaying a subset of data items from each Patient/Service User Record returned in the results   - Number of Patients/Service Users grouped by age range   - Drilling down to an individual Staff Member level or Health or Care Professional type level  ---  E00347 - schedule the automated running of reports As a Health or Care Professional  I want to schedule the automated running of reports  So that I do not have to run the reports manually Acceptance criterion 1: create report schedule Given a Health or Care Professional is permitted to run reports  When the Health or Care Professional selects to schedule the automatic running of a report  Then the report is scheduled Acceptance criterion 2: automatically run report Given a report has been scheduled to automatically run  When the scheduled time is reached  Then the report is run automatically E00347 - Supporting Information  - Scheduling MAY include, but is not limited to:    - On a specified date   - At a specified time   - On a recurring basis  ---  E00348 - save locally defined reports As a Health or Care Professional  I want to save locally defined reports  So that the report criteria do not need to be defined each time the report is run Acceptance criterion 1: save locally defined report Given a Health or Care Professional is permitted to manage locally defined reports  When the Health or Care Professional selects to save a locally defined report  Then the report is saved   ---  E00349 - save report results As a Health or Care Professional  I want to save report results  So that I can view them without having to re-run the report Acceptance criterion 1: save report results Given a Health or Care Professional is permitted to view report results  When the Health or Care Professional selects to save report results  Then the report results are saved Acceptance criterion 2: view saved report results Given a Health or Care Professional is permitted to view report results  When the Health or Care Professional selects select to view saved report results  Then the report results are displayed   ---  E00350 - export report results As a Health or Care Professional  I want to export report results  So that reports can be viewed outside of the Solution Acceptance criterion 1: export report results Given a Health or Care Professional is permitted to export report results  When the Health or Care Professional selects to export the report results  Then the report results are exported E00350 - Supporting Information  - Report results export formats MAY include, but are not limited to:    - .XLSX   - .DOCX   - .PDF  ---  E00351 - print report results As a Health or Care Professional  I want to print report results  So that reports can be viewed outside of the Solution Acceptance criterion 1: print report results Given a Health or Care Professional is permitted to view report results  When the Health or Care Professional selects to print the report results  Then the report results are printed   ---  E00352 - share access to a report within my Health or Care Organisation As a Health or Care Professional  I want to share access to a report with other users in my Health or Care Organisation  So that other users in my Health or Care Organisation can use the report Acceptance criterion 1: share access to report within my Health or Care Organisation Given a Health or Care Professional is permitted to create reports  When the Health or Care Professional selects to share access to a report within their Health or Care Organisation  Then access to the report is shared with other users   ---  E00353 - share report with another Health or Care Organisation As a Health or Care Professional  I want to share a report with another Health or Care Organisation  So that reports can be shared between Health or Care Organisations Acceptance criterion 1: share report with another Health or Care Organisation Given the Health or Care Professional is permitted to share reports  When the Health or Care Professional selects to share the report with another Health or Care Organisation  Then the report is shared Acceptance criterion 2: run shared report Given the Health or Care Professional is permitted to run reports  When the Health or Care Professional selects to run a report that has been shared  Then the report results are displayed   ---  E00354 - identify the reason a Patient/Service User meets each report criterion for a report As a Health or Care Professional  I want to identify the reason a Patient/Service User meets each report criterion  So that I can see why the Patient/Service User was included in the report results Acceptance criterion 1: identify the reason a Patient/Service User has been included in report results Given a Health or Care Professional has run a report  When the Health or Care Professional selects to identify the reason a Patient/Service User has been included in the report’s results  Then the Health or Care Professional can see how the Patient/Service User meets each report criterion E00354 - Supporting Information  - For example, for a report with three specified criteria, provide a reason for how a given Patient/Service User met each criterion  ---  E00355 - identify which report criteria a Patient/Service User does not meet As a Health or Care Professional  I want to identify which report criteria in a report a Patient/Service User does not meet  So that I can see which report criteria caused the Patient/Service user to be excluded from the report results Acceptance criterion 1: identify which report criteria the Patient/Service User did not meet Given a Health or Care Professional has run a report  When the Health or Care Professional selects to identify why a Patient/Service User was excluded from a report’s results  Then the Health or Care Professional can see which report criteria a Patient/Service User does not meet E00355 - Supporting Information  - For example, for a report with three specified criteria, indicate for a given Patient/Service User which criteria they met and did not meet (the Patient/Service User may not be in the overall report results, but may meet some of the criteria)  ---  E00356 - perform analytics As a Health or Care Professional  I want to perform analytics  So that I can visualise the data, gain insights and identify trends Acceptance criterion 1: perform analytics Given a Health or Care Professional is permitted to perform analytics  When the Health or Care Professional selects to perform analytics  Then analytics are be performed E00356 - Supporting Information  - Analytics MAY include, but is not limited to:    - Visualisation of data (e.g. graphs, charts etc.)   - Tracking data against KPIs and targets   - Identification of trends and anomalies   - Future predictions based on historic data   - Test potential scenarios and recommend actions |
