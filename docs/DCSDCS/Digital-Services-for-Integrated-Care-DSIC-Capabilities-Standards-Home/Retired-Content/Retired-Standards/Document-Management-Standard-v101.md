# Requirements

| Epic Mapping | Requirement ID | Requirement Text | Level |
| --- | --- | --- | --- |
| C9E15 | **GP-DM-4.1-03** | **Document capture/receipt - Electronic formats**  Automatically handle electronic documents of varying format into the Solution from pre-defined areas/methods for processing and conversion to industry standard formats e.g. TIF or PDF/A (an ISO Standard archival document format) for publishing. | MUST |
| C9E15 | **DOCMAN01** | **Documents available in non-proprietary formats**  Documents are to be made available in a timely manner, in non-proprietary formats in adherence with GP2GP (see requirement S50 in GP2GP R2.2 Requirements Specification). Proprietary formats should be converted as required.  Supplier to ensure that the integrity of documents processed by the Solution when transferred as part of GP2GP (either as a complete document or as a link) can be preserved at the receiving practice with context intact.  The documents can therefore be viewed within the appropriate part of the patient record with any mark ups and annotations intact. | MUST |
| C9E16 | **GP-DM-6-01** | **Access Patient Record**  Access a Patient Record where a Patient has been successfully identified, linked, listed or otherwise presented to the user. | MUST |
| C9E1 | **GP-DM-7-01** | **Document classification**  Manually classify documents using:   - Correspondence Care Setting Type - Correspondence Document Type - Clinical/non-clinical flag/status | MUST |
| C9E2 | **GP-DM-7-02** | **Document Properties**  Manually record and update document properties for:   - Header file - Document metadata | MUST |
| C9E3 | **GP-DM-7-03** | **Document Attributes**  Manually record and update  document attributes such as:   - Document type - Category - Source | MUST |
| C9E4 | **GP-DM-7-04** | **Coded Entries**  Manually code clinical entries and store in the Patient's record by:   - Coding from a review of a document - Recording values associated with a code   For further information, see SNOMED CT | MUST |
