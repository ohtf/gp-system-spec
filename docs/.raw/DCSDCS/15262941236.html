Introduction

The Validated Relationship Service - FHIR API enables a Solution to access the Validated Relationship Service. This is the national electronic database of relationships that have been verified for the purpose of enabling individuals to access healthcare services on behalf of those they care for. The relationships held by this service are strictly for the purpose of enabling access to healthcare services.

VRS02

Reliability - Retries

The GP Practice Solution must attempt a minimum of 3 retries (with a configurable option to extend to 5) before classifying a request to the Validated Relationship Service as failed.

MUST

VRS03

Performance - Data Processing

Proxy role data must be processed and made available in the GP IT System within 5 minutes of receipt of the MNS event notification from MNS, measured end-to-end.

MUST

VRS04

Reliability - Dead Letter Queue (DLQ)

Unprocessable events or requests stemming from background processing must be published to a Dead Letter Queue (DLQ) for investigation and out-of-band processing.

MUST

VRS05

Reliability - DLQ Retry

Events or requests in the DLQ must be retried after the cause of failure has been resolved, within 1 working day.

MUST

VRS06

Reliability - Exponential Backoff Strategy

Retry logic for failed request processing must follow an exponential backoff strategy to prevent system overload and ensure safe reprocessing.
