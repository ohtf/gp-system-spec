Data Recording and Transfer

Community Pharmacy Solutions need to maintain comprehensive and accurate clinical records to support safe and effective ongoing service delivery.

The following table is derived from the Community Pharmacy Contraception Service requirements and outlines the Data Transfer and Recording for each Pharmacy Contraception Consultation record. The columns define:

  • Pharmacy Contraception Service Consultation Record - Data elements that must be collected and retained within the Pharmacy Contraception Service Consultation record

  • Implementation Guidance - Implementation guidance to ensure data quality and consistency

  • Mapping to NHSBSA Claim API Interface - Data items that must be submitted to the NHS Business Services Authority (NHSBSA) to support claims and reporting as per the NHSBSA Claims & Reporting Standard. Fields marked with '-' signify that data does not flow to the NHSBSA.

  • Mapping to GP Connect Update Record API interface - Data items that must be shared with the Patient’s registered GP Practice following a Pharmacy Contraception Service Consultation as per the GP Connect Update Record Standard, to enable continuity of care. Fields marked with '-' signify that data does not flow via GP Connect Update Record.

    Links to GP Connect Implementation Guide and Specifications are provided for data fields that are shared with the Patient’s registered GP Practice. They are provided as a reference and Suppliers are expected to fully understand the implementation requirements and comply with the GP Connect Update Record Standard.

49

Medication Name (dm+d) 

  • Allow a maximum of 1 product row; Multiple packs of same product are allowed (e.g. double-dose for EC). Hard error if > 1 product row

  • Ensure UI prevents entry of medication data, if Outcome of Contact(Consult_outcome) is one of the No Supply values. The system must not generate a MedicationDispense or populate the products array

  • For any product selected, the system must automatically populate both views:

    • Pack level - VMPP or AMPP code for NHSBSA Claim as NHSBSA CLAIM API enables payment and post-payment verification at Pack level (quantity, pack size)

    • Product level - VMP or AMP code for GP Connect Update Record API as this provides clinically appropriate “what was supplied” rather than pack artefacts

No supply reason

  • Context-filtered list by Outcome of Contact and Service Type

  • No supply reason is mandatory, if Outcome of Contact(Consult_outcome) is one of the No Supply values (as per BSA API spec logic)

  • Multiple codes are allowed

  • Guidance on selecting noSupplyReason codes:

    • If Consultation outcome is NO_SUPPLY_SIGNPOSTED or NO_SUPPLY_ESCALATED, then restrict noSupplyReason options to codes B–S and U–Z (based on service context: OC/OEC/both)

    • If Consultation outcome is NO_SUPPLY_OTHER, then set noSupplyReason option to ‘T – Other (please state)’. A free text box must be displayed to capture additional information

    • If Consultation outcome is NO_SUPPLY_PATIENT_DECLINED, then set noSupplyReason option to ‘A - Consent not given’
